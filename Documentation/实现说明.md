# 拍后景深 v2：代码实现说明

## 范围

保留原相机 Demo 的预览／拍照／保存流程。仅静态拍照后添加景深，最低 iOS 17，纯 Swift 调用 Apple 原生框架。不做实时景深、导入普通照片生成深度、AI 模型兜底、持久化对焦或拍后重新对焦。用户提供的照片与截图是目标参考，不是本 Demo 的实测样本。

## 数据链路

`AVCapturePhotoOutput` → 同次 `AVCapturePhoto.depthData` → `NativeDepthSnapshot` → `DepthRaster` → `DepthPlan` → `DepthBlurRenderer` → 最终 CGImage → `EffectMeasurement` → `ProcessedPhoto` → 完整成片 JPEG 保存。

相机会话和请求状态封闭在 sessionQueue，渲染封闭在另一条串行 renderQueue，UI 留在主线程。`AVDepthData` 先转换为 DisparityFloat32，然后按照 CVPixelBuffer 实际每行字节数复制成 Swift 数组；没有把行填充当成像素，也没有跨队列共享可变像素缓冲区。

照片回调按 `uniqueID` 关联，等待拍摄最终回调再恢复 continuation。45 秒兜底只针对相机拍摄回调，不等于景深渲染耗时保证。所有失败分支仍有普通照片或明确错误返回；没有新增长时间实时深度流。

本版将 `embedsDepthDataInPhoto` 设为 false，因为渲染直接消费照片回调中的深度。未使用“先保存再从 HEIC 取出深度”的链路。最终重新编码 JPEG，仅写图像质量和方向白名单，不复制原文件的私有相机元数据或深度附件。

## 点选与对齐

原 Demo 先通过预览层将点选坐标转换成硬件对焦点。相机只保留“本轮用户有点按”的布尔状态，在快门时读取设备当前的点位，作为这一次拍摄的临时参数。变焦、切换配置、停止或一次消费后清除此状态。处理输出不包含点位，没有 JSON／磁盘持久化或坐标日志。

未点选时，使用 Vision 的原生人脸矩形检测来选一个有深度的区域，不做人像分割，也不把人物整体替换为清晰层。多人场景默认优先最大人脸，非人像场景默认中心；更明确的选择应由用户拍前点按完成。

原图、深度栅格和本次点位统一应用同一个 EXIF 变换。栅格定义为左上原点，包含全部八种旋转／镜像；最终原图原点归零。图像／深度长宽比差异大于 2% 时明确降级，不拉伸错配数据。比率检查不能证明同宽高数据一定完美配准，前后镜头实际方向及边缘仍需真机验收。

## 深度数值与虚化量

只使用有限且正的视差。有效像素不足 25%，或稳健的 2%～98% 深度范围几乎无差异时，停止制造景深。选择点附近取小区域中位数，中心有效时优先取相近深度簇；区域不足则提示重新点选，而不是把未知值当成最远背景。

相对于焦平面的有符号视差差值决定前后关系。清晰带内半径为零；超过清晰带的程度决定 0～1 的连续虚化量，近、远分别处理。人脸仅帮助选取焦平面及稍微放宽清晰带。同深度的桌子、椅子或另一个物体采用相同规则。

当前数字属于效果标定而不是物理镜头模型：f/1.4 时 1600 像素长边上的最大半径为 32，f/16 时为 0.8，其他档位递减。实际每个像素半径还乘以该像素的虚化量，因此“最大半径”不代表整张背景都同样模糊。半径随处理／输出长边缩放，f 值同时影响清晰带宽度。相对精度的深度不宣称精确测距。

## 渲染

采用 Core Image 的 `CIMaskedVariableBlur`，黑色掩膜不模糊、白色达到最大半径、中间灰度控制强弱。[Apple 接口说明](https://developer.apple.com/documentation/coreimage/cifilter-swift.class/maskedvariableblur())

低分辨率虚化量经 `CIEdgePreserveUpsample` 以上采样的 RGB 图像作为边缘引导。滤镜无输出时使用明确记录的双线性路径，不冒充已完成细节修复。[Apple 参数说明](https://developer.apple.com/documentation/coreimage/ciedgepreserveupsample)

远景先排除清晰／近景颜色，再对带透明覆盖的远景层模糊。模糊后的 RGB 按覆盖率归一化，避免直接与黑色混合。近景独立模糊，并扩展其模糊影响范围；底层原先锐利的近景轮廓用周围可见像素的归一化填色替代，再合成近景，减轻锐利轮廓残留。这只是可见像素外推，不是恢复被遮挡的真实背景。

覆盖率归一化使用 `unpremultiplyingAlpha()` 和 `settingAlphaOne(in:)`。掩膜作为数据处理，输入及物化中间结果禁用颜色空间变换，避免把灰度数值当作照片进行伽马转换。[Apple alpha 操作说明](https://developer.apple.com/documentation/coreimage/ciimage/settingalphaone(in:))

虚化层最大长边为 2048，在小尺寸处分段物化，再与完整分辨率原图通过影响范围合成。清晰区域仍取原图，不把整张缩略图冒充全分辨率输出。复杂遮挡、细线、透明物体、深度孔洞可能出现光晕或漏虚；这一近似算法仍需真实照片调参，不能保证参考 App 的散景形状和边缘精度。

## 输出检查不是画质判定

对实际最终 CGImage 进行缩小采样，在目标虚化量足够的区域比较处理前后 RGB。eligiblePixels、meanChange、changedPixels 是差异指标，不是“模糊正确率”。发生足够变化时显示 `applied`，变化不足时显示 `weakEffect`；纯色墙面即使执行正确的模糊也可能被标记弱变化，这是有意保守的提示。

处理失败、无深度、无层次、点选处缺少有效深度、比例不一致都有各自状态，禁止把普通图提示成景深成功。用户最终需要通过同一次照片的按住对比和实际成片检查虚化是否符合目标。

## 当前限制

未增加自动寻找所有 activeFormat 的复杂格式切换，仍基于当前原生相机拍照配置查询能力。默认候选相机及支持情况会写入日志，可据真机诊断继续定位“不支持／未交付”。不能根据 iPhone 名称跳过能力检查。

未实现可靠深度的 AI 修补、实例分割、用户手动蒙版、光斑形状参数、焦点持久化或图库重编辑。普通光学失焦、手抖和运动模糊不可由此消除。Vision 只调用系统检测，不提供或下载独立模型。
