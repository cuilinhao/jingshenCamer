# 实现与检查备注

本次是在上传工程现有拍照流程内替换 CameraManager 并扩展 ViewController，没有引入视频帧处理链。原 Storyboard、素材、相册写入交互保留。异步线程划分为 UI/MainActor、sessionQueue、renderQueue，工作类型没有使用隐式 MainActor 隔离。

- 原生照片输入：候选相机逐一接到 photoOutput 后检查当前照片深度能力，优先后置 dual-wide/dual/triple/LiDAR 或前置 TrueDepth，无能力时使用普通广角。
- 原生深度只与同次照片配对；通过内存中的照片文件读取辅助深度，不读取实时 depth stream，不使用人像掩码伪造杯子的景深。
- 使用 supportedMaxPhotoDimensions 选择真实支持的尺寸；不强行写不支持的48MP或12MP数值。变焦遵守 minAvailable/maxAvailable，避免虚拟双摄在深度模式下写越界值。
- didFinishProcessingPhoto 仅暂存结果，didFinishCaptureFor 才结束本次请求；uniqueID 匹配和超时保护防止迟到回调恢复错误的 continuation。
- 将 RGB 和 AVDepthData 用同一个 EXIF orientation 转正，滤镜 orientation 设 up，不重复应用方向。保留原生视差数据，不做普通灰度 min-max 归一化。
- 使用 CIContext.depthBlurEffectFilter 工厂，并检查其 inputKeys 后设置 inputAperture，不调用 setDefaults 清掉工厂配置；本版不设定计算焦点矩形。
- createCGImage 实际渲染后再编码，避免仅生成惰性的 UIImage(ciImage:) 冒充成片完成。缺深度或滤镜创建/渲染失败回退普通照片。
- 最终只保存重新编码的普通 JPEG；Maker/辅助深度/焦点等相机元数据不被复制；没有任何焦点持久化接口。

## 测试先行记录

第一次增加源码契约检查、未修改 App 实现时，8 项检查中 6 项失败、2 项通过，失败覆盖新增深度能力、处理器、原生设备选择、正确保存与部署/隔离要求等。新增 iOS 17 场景方向兼容检查时，单独执行得到预期失败，再把高版本 Geometry 访问改成旧版可用的场景接口。

最终检查结果见 verification-local.txt。源码契约是文本结构回归，不能验证 Apple SDK 接口拼写/类型、设备支持状态、滤镜默认焦点、运行时并发行为或视觉效果。纯 Swift 规则检查只验证它们所覆盖的数值与状态逻辑。没有把这些检查描述成 Xcode build、XCTest 或真机测试。

## 仍需真机确认

不同摄像头的深度交付质量、非人脸场景的系统自动清晰面、虚拟光圈视觉差异、边缘伪影、前后摄像头镜像与横屏对齐、性能/内存峰值、权限和中断恢复，都需要按真机验收文档运行。景深开关关闭只停止请求/处理当前照片的深度，已配置的拍照深度管线保持准备状态，以免每次切开关重建会话。
