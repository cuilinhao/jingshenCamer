# 2026-09-22 苹果景深接入与验证

## 实现

- 默认调用公开 `CIContext.depthBlurEffectFilter(forImageData:options:)`，设置虚拟光圈与本次焦点。
- 原生采集的 RGB、深度、人物及可用头发/眼镜遮罩在同一内存容器传递。仅最终烘焙 JPEG 可保存到相册。
- 苹果路径不调用旧版深度半径算法，不做整个人物原图强行覆盖。旧版作为同帧对照，结果页按住查看，不影响保存目标。
- 默认 f/1.4，桌面名称“TestCamer 苹果景深”、页面版本 v3。
- 官方内部虚化遮罩不公开，诊断图明确标为输出差异图。

## 原生接口实测

容器 factory 的输入/输出保持原始传感器方向。`inputFocusRect` 在该图像中使用归一化左下原点坐标；输入焦点从左上原点换算后设置，末尾统一应用 EXIF。采用不对称、不同深度的纹理夹具，验证八种 EXIF/镜像、非中心选焦及 f/1.4 与 f/16 的实际纹理变化。

当前 Mac runtime 在带部分原生辅助元数据时，官方滤镜直接返回同一个输入 CIImage 对象。已通过像素逐项相等验证这个直通现象。仅在该明确条件下，清除 `inputAuxDataMetadata` 及视差图继承的对应元数据包装，重用同一个苹果滤镜处理。原始视差值、其余图像属性、独立标定输入和辅助遮罩保持不变；结果页和诊断明确显示“苹果景深（兼容）”。不是静默换回旧算法。

辅助元数据兼容处理属于本次实测的运行时适配，不是苹果文档承诺的系统相机完整成像流程。实际 iPhone 18 上是否需要该兼容路径、边缘表现和处理耗时，需新拍样本确认。

## 验证记录

- 本轮先运行新增失败回归，再接入处理逻辑。最初默认路径没有官方输入时仍跑旧版，新增的两项拒绝误替代检查失败；接入后通过。
- 苹果适配器测试直接编码包含原生辅助视差的 HEIC、实际执行 Core Image，不以滤镜对象非空作为成功标准。
- `Scripts/verify_on_mac.sh` 覆盖纯 Swift 规则、TestLog、现有结构检查、iOS SDK 不签名构建、原有/全链路渲染与新增苹果渲染测试。
- 离线回放使用同一未虚化合成场景的分离 RGB/aux 容器，EXIF 6；两套算法均输出 512×768 成片，状态 applied。
- 独立静态审查覆盖选焦/方向、辅助数据、兼容路径、同帧对比、保存、元数据清理和相机能力配置，未发现重要问题。
- 最终测试统计与构建结果在本说明末尾记录。

## 真机验收边界

用户的 `iPhone18tu.heic` 已有系统虚化。它只用于理解目标及输入结构，没有把二次虚化当作效果验收。

本轮没有安装、启动或操纵任一连接的实体手机，也没有声称已达到系统相机相同画质。下一次真机使用 f/1.4，点选同样的前景人物，重点比较后排人物、黑色衣物、椅背、发丝和前后手臂；按住旧版与原图检查连续性，再检查相册里的完整 JPEG。需要结合导出的 TestLog 确认实际使用原生还是兼容路径。
