# 主摄苹果景深恢复

分支：`codex/apple-depth-rendering`。用户确认允许主摄使用辅助双摄或 LiDAR 获取原生深度，RGB 成像镜头仍固定为主摄。

## 原因

三镜头初次实现把所有镜头默认改为计算景深，原生深度也由自定义渲染器处理；独立主摄输入还可能不交付原生深度。这两处变化使主摄效果与此前苹果 API 版本不同。此前的 `AppleDepthRenderer` 本身没有被替换或修改。

## 最终行为

| 镜头 | 采集 | 拍照与后续编辑 |
| --- | --- | --- |
| 主摄 | 物理主摄 ID 固定；优先可明确锁定该主摄的双摄/三摄，再尝试能核实同一主摄配对的 LiDAR；否则独立主摄 | 有效原生深度优先使用原 `CIContext.depthBlurEffectFilter`；保留原生容器，编辑继续使用苹果滤镜 |
| 超广角 | 指定独立物理输入 | 原生深度可用时使用，否则本机估计；均使用计算景深 |
| 长焦 | 指定独立物理输入 | 原生深度可用时使用，否则本机估计；均使用计算景深 |

明确指定 constituent 的锁定 API 从 iOS 27 提供，运行时还检查设备能力，源码构建需要包含 iOS 27 SDK 的 Xcode。不使用“先变焦后猜测当前主镜头”的方式。在快门前校验实际主摄 ID 和锁定状态；无法确认时尝试明确重新锁定，再退回所选独立主摄。恢复过程保留本次用户点按，重新配置硬件对焦；无法恢复则本次快门报错。数码变焦显示以物理主摄原生视场为 1×。照片关闭虚拟设备 RGB 自动融合，保留原生深度请求。

主摄原生深度缺失或苹果处理失败时仍可回退计算景深；诊断包含 `preferredRenderer=apple`、`appleFallbackReason` 和 `actualRenderer`。苹果结果不写计算深度附件，计算结果保留独立附件，保证重开编辑维持首次处理路径。此前已保存的计算景深照片保持原样。

## 验证记录

- 主摄路由回归先复现 11 项中 5 项失败，修复后 11 项全通过：自动主摄输出与显式旧苹果路径像素一致，重开编辑一致，其他镜头和显式对照保持原路径，缺原生容器或深度时诚实回退。
- 主摄辅助输入策略 20 项通过：精确物理 ID、旧系统拒绝不支持明确锁定的双摄、LiDAR 唯一 RGB 配对、超广角/长焦排除辅助输入、虚拟倍率换算及融合照片拒绝。
- `verify_on_mac.sh` 完整运行通过，日志 `/tmp/testcamer-main-restore-verification.log`：iOS Debug 通用真机 SDK 构建成功；原生渲染 94、苹果渲染 58、存储 98、编辑状态 30、苹果编辑 145、计算渲染 43、模型基础 23/真实模型 27、计算流程 71、主摄路由 11 项通过。苹果前景虚化的 8 项已知限制仍单独报告，没有算作画质验收通过。
- 渲染与持久化独立审查未发现新增缺陷；采集独立审查提出身份校验降级失败时应恢复相机会话，已修复。随后检查并修复了恢复过程清除用户点按焦点的问题。最终所有源码 SDK 类型检查与增量 iOS 构建通过，日志 `/tmp/testcamer-main-restore-final-build.log`；策略 20 项再验证通过，`git diff --check` 无错误。

## 真机边界

尚未证明目标 iPhone 实际交付了原生深度，或真实场景效果已恢复。读取测试手机日志时设备连接立即断开，没有取得设备日志。没有安装、启动或触发真机拍照。

新拍主摄照片应显示“苹果景深”或“苹果景深（兼容）”，且重新打开编辑后保持同一路径；若显示智能景深，查看导出的 TestLog 中辅助输入被拒绝或 `appleFallbackReason` 的原因。拍摄步骤见 `2026-09-22-三镜头智能景深验收.md`。

恢复苹果原流程也保留其已有边界：公开滤镜在某些合成输入上，点远处时前景不明显虚化；不能据 API 接入宣称与系统相机画质一致。实际验收需同场景、相近构图与距离、同焦点和 f 值比较。
