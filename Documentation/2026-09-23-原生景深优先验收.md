# 2026-09-23 原生景深优先：验收方案

本次调整目标：后置主摄和前置优先使用原生深度与苹果景深滤镜；原生深度不可用或苹果渲染失败时，用同次原图运行离线模型兜底。后置超广角、长焦继续使用模型。保留物理镜头身份核验、已有照片和缓存深度编辑。

**状态：以下真机项目均待测。** 本文不代表已在 iPhone 上验证深度交付、画质或耗时改善。此前的耗时证据与 API 复核保留在 [景深成片耗时排查](2026-09-23-景深成片耗时排查.md)，历史测量不能作为新实现的验收结果。

## 路线与能力边界

| 选择与条件 | 拍摄及处理路线 | 编辑与重开 |
|---|---|---|
| 后置主摄，身份验证通过并交付可用原生深度 | 原生深度 → 苹果景深滤镜 | 保留原生容器，继续苹果渲染 |
| 前置，TrueDepth 等实际配置交付可用原生深度 | 原生深度 → 苹果景深滤镜 | 保留原生容器，继续苹果渲染 |
| 后置主摄或前置，原生深度不可用或苹果滤镜失败 | 同次原图 → 模型估深 → 智能景深，记录回退原因 | 保存 estimated 深度附件，调焦与调光圈复用附件 |
| 后置超广角、长焦 | 所选物理镜头原图 → 模型估深 → 智能景深 | 复用已保存的估计深度 |
| 景深关闭 | 普通照片 | 不运行模型 |
| 模型估深或智能渲染也失败 | 普通照片与明确失败提示 | 不把失败结果标为景深成功 |

系统版本不是原生深度能力的替代指标。iOS 26 仍需按输入、格式、变焦及 photo output 的实际支持状态配置，再核对本次快门是否交付有效深度。编译工程使用包含 iOS 27 SDK 的 Xcode，不代表运行必须使用 iOS 27。

后置双摄/三摄在支持时使用指定 constituent 的锁定 API。旧系统的兼容流程必须先启动会话，核实 `activePrimaryConstituent` 是选定的物理主摄，再调用旧版 `.locked` 锁住当前 primary；之后重新核实请求/活动锁定状态、主摄身份、变焦与深度能力。`.locked` 本身不能指定另一颗镜头，某个 zoom 值也不证明 primary 已切换成功。primary 缺失、指向另一镜头或锁定无效时，不能把该组合输入当作已保证主摄。

LiDAR 使用独立的配对判断：实际输入必须仍与所选唯一物理 RGB 主摄匹配。前置照片不应用后置主摄的来源限制。无法保证后置所选镜头时，退回同一物理主摄；不能为了获取深度接受其他镜头的 RGB。

| 前置原生景深 | 切换前置并拍摄；界面显示苹果景深优先，实际取得原生深度并成功时标为苹果；不被后置主摄来源判断误拒绝 | 待测 |
| 前后摄往返 | 前置与后置重复切换、拍照、返回重拍；照片左右方向、镜像、点选焦点和深度对齐一致 | 待测 |
| 数码变焦与重置 | 主摄捏合后拍摄，再点当前镜头恢复原生视角；验证身份、锁定与深度支持，不把 zoom 当作主摄身份依据 | 待测 |
| 无可用原生深度 | 在不支持的真实配置中拍主摄/前置；显示本机估计，日志带回退原因，结果为 computational、estimated | 待测 |
| 苹果滤镜失败 | 可复现失败输入或合成注入验证：即使仍有原生附件，也运行模型估深；结果和缓存深度来源均为 estimated | 待测 |
| 模型也失败 | 受控失败输入或测试注入验证：保留普通照片与原因，不能显示苹果/智能景深成功 | 待测 |
| 景深关闭 | 主摄、前置、超广角、长焦各拍一次；得到普通照片，不加载或运行模型 | 待测 |
| 预览到结果的说明 | 拍前显示能力与优先路线；拍后和编辑页按实际渲染结果标识，自动回退时说明苹果路径不可用与智能景深回退 | 待测 |
| 缓存编辑和重开 | 分别保存苹果结果和模型兜底结果，换焦、调光圈、返回列表、重启重开及导出；沿用原生容器或缓存深度，编辑不再次估深 | 待测 |
| 旧智能景深照片 | 重开已有缓存深度照片并编辑，保持原有文档可读，不自动冒充新拍的苹果路线 | 待测 |
| 会话中断恢复 | 后台/前台或系统中断恢复后再拍；重新验证所选镜头身份与适用锁定，失效时安全回退或明确失败 | 待测 |

无法在真机稳定制造的处理失败，应记录为“合成注入已测、真机未复现”，不能将其记成真机通过。对只有 LiDAR 的实际路线，也不能据此认证双摄旧锁定流程已通过。

## 证据与耗时记录

同一次快门通过 capture ID 关联配置、采集、处理和显示日志。至少保留：所选镜头与实际输入、primary 原始身份、请求/活动锁定、深度请求与交付、`prefersAppleDepth`、最终 renderer、深度来源，以及存在时的 `appleFallbackReason`。界面显示“苹果景深优先”只表示策略，不证明本次滤镜成功。

验证模型兜底时核对缓存附件的 `source == estimated`；验证后续编辑时确认沿用该附件。只有最终苹果成功才记为苹果路径；苹果滤镜的元数据兼容模式仍是苹果滤镜，不能混同模型兜底。

耗时比较须在同一真机、同场景和近似分辨率下记录首次拍摄与后续至少三次拍摄。区分快门交付、处理和本机保存，另记录是否执行模型及其冷/热状态。原生路线的实现或合成测试通过，均不能单独证明端到端成片更快。
