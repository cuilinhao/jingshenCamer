# v2 修订与验证记录

## 已知事实与不能断言的部分

用户反馈上一版成片没有明显虚化。用户上传的杯子、人像和普通取景截图是希望实现的效果，不是上一版 Demo 输出。此次没有收到上一版真机输出文件、运行日志或原生深度文件，因此没有把运行失败归因于某一设备、系统接口或某张参考图。

从上一版代码可确认两点：第一，交给处理器的是编码照片与 hasDepth 布尔值，处理器需再次从容器附件还原深度；第二，只要原生景深滤镜返回可渲染图像，就标记景深成功，没有检测输出是否确实变化。上一版算法焦平面依赖系统自动选择，未把普通硬件点按明确送入算法选焦。

这些是实际代码结构与可验证缺口，并不能证明所有“没有虚化”的现场根因已经确定。v2 去掉了附件重读依赖，增加显式近远景控制和诊断，使后续实测可定位，不把改完代码当作真机已经修复。

## 改动审查

修改集中在现有照片管线、深度数值、结果对比与诊断。保留原相机 UI、项目入口、原生候选设备、会话串行队列、中断、回调 ID 和完整尺寸保存路径。没有加入联网、账号、第三方 SDK 或额外模型；没有把参考人物图硬编码为测试输入或 App 资源。

审查重点包括：同次照片与深度关联；像素行填充；八种 EXIF 方向；有限值／深度孔洞／极值；f 值随像素尺寸换算；近景和远景不是同一个全图蒙版；Alpha 归一化及掩膜颜色空间；最终完整图像输出；对焦参数不持久化；实际差异与画质保证的区分。

此审查在当前环境内完成，没有独立子代理审查或 Apple 平台实测。不能把源码审查标成 Xcode 构建通过。

## 回归验证

先在上一版执行原有检查：25 条纯 Swift 规则和 9 项旧源码检查通过，说明旧测试未覆盖用户反馈的效果问题。

新增“直接传递深度值”“显式近远景渲染”“最终输出变化检查”的回归断言后，在上一版出现预期失败，再在 v2 实现。纯 Swift 数值部分另有实际编译运行的样本，不仅用查找源码字符串来判定数学逻辑。

最终本地检查的实际输出保存在 `verification-local.txt`。本地范围：25 条原有规则、58 条数值／边界检查、15 项源码结构检查，Swift 语法解析和工程资源格式检查。源码字符串回归只防止管线结构退化，不证明 SDK 契约或运行效果。

## 未执行项

未运行 iOS SDK 类型检查、Xcode 构建、签名安装、iPhone 相机、原生 Core Image 渲染或视觉对照。Mac 原生测试文件已加入，但当前 Linux 没有 Apple 框架，不能执行。脚本的 Linux 环境守卫返回 2 并标明 NOT VERIFIED，这属于拒绝误跑，不是测试通过。

## 已知待验证风险
