# TestCamer · 三镜头智能景深

原生 iPhone 相机实验项目。选择超广角、主摄或长焦，固定所选 RGB 成像镜头。主摄允许双摄或 LiDAR 辅助提供原生深度，优先恢复苹果原生景深；超广角、长焦使用智能景深。缺失有效原生深度时使用离线 Core ML 深度估计。实现与合成测试不等于已经通过系统相机同等画质验收。

## 使用流程

用包含 iOS 27 SDK 的 Xcode 打开 `TestCamer.xcodeproj`，选择 TestCamer Scheme 和 iPhone 真机运行。最低运行系统仍为 iOS 17.0；签名使用自己的开发 Team。桌面名称保留 **TestCamer 苹果景深**，拍摄页根据实际能力显示苹果或智能景深。Core ML 模型随 App 编译打包，首次处理包含模型加载耗时，运行时无需联网。

1. 允许相机权限，保持景深开启，默认光圈为 **f/1.4**。
2. 点选前面的清晰主体，等物理对焦稳定后拍摄。普通取景不实时虚化。
3. 有效景深成片先保存在本机，并自动进入**景深编辑**。点击照片内不同位置换焦；f/1.4～f/16 滑杆调整景深。点击照片之外的留白不改变焦点。
4. **按住看原图**查看未虚化预览；**恢复初始**回到首次拍摄的焦点和光圈。新操作会合并，只有最新一次渲染结果更新画面；失败保留上一效果并提示原因。
5. 每次成功编辑自动保存本机版本。**完成**返回；拍摄页左上角**可编辑照片**可重新打开，关闭或重启 App 后仍可继续编辑。列表左滑可删除整份本机原图、深度与编辑记录，不删除相册成片。
6. **保存到相册**冻结当前参数，从完整原图重新渲染全尺寸 JPEG。保存过程中禁用编辑，防止当前画面与导出参数错配。
7. 首次拍摄进入编辑页后，右上角**拍摄对照**可查看原图、初始智能景深及诊断；这些对照不改变当前编辑。重开本机照片保留原图和可编辑效果。
8. 深度估计或渲染失败时，显示普通成片与原因，可直接保存普通 JPEG。平坦场景保留原图并提示弱效果，不强行虚化。点击深度孔洞时保留上一编辑效果，提示重新选点。

没有点按时，选择最大的可用人脸中心，否则选择画面中心。主摄苹果景深照片保留原生容器，之后编辑继续使用苹果滤镜；智能景深照片缓存独立深度，调焦不重复估计深度。编辑页显示实际使用的景深类型，首次自动回退时说明原因。此前保存的智能景深预览不会自动改写，再次调焦、调光圈或导出时采用更新后的智能渲染。显式苹果/旧版离线对照仍保留。

## 物理镜头切换

快门上方显示设备实际拥有的 **超广角 / 主摄 / 长焦** 按钮，默认主摄，前置隐藏这排按钮。每个按钮绑定物理摄像头的设备 ID。主摄优先选择能明确锁定该主摄的双摄/三摄输入，或仅包含该 RGB 镜头的 LiDAR 输入，辅助相机只提供深度；超广角、长焦使用各自独立输入。无法保证指定主摄时退回独立主摄。没有对应镜头的设备不显示该按钮；指定镜头切换失败时提示错误并尝试恢复原镜头。

点击镜头从它的原生视角开始；捏合仅进行当前镜头的数码变焦，镜头高亮保持不变，再点当前镜头可重置数码变焦。顶部显示实际镜头、变焦及景深状态。

主摄的明确 RGB 锁定使用 iOS 27 提供的 constituent 指定锁定 API，并检查设备是否支持；较早系统仅在能确认 LiDAR 与所选主摄配对时使用辅助深度，否则使用独立主摄。所选镜头没有有效原生深度时，从该镜头拍下的原图估计相对深度，不更换 RGB 镜头。景深开关和虚化调节对三个镜头均可用；界面标明主摄苹果景深优先或本机估计。估计图只表达远近关系，不是精确米数，也不伪装成相机交付的 AVDepthData。

## 智能景深实现

- 模型采用 Apple 提供的 Depth Anything V2 Small FP16，模型文件约 49.8 MB。来源、许可和校验值见 `TestCamer/Models/`；包内实际模型输入为 RGB 518×392。
- 照片先应用 EXIF；模型读取完整图像，不中心裁切，输出恢复图像比例。保存时变换回传感器坐标；编辑时与照片统一应用方向，覆盖旋转与镜像。
- 近景和远景分别生成虚化层，RGB 引导上采样细化边界；清晰区域使用完整分辨率原图。不会把整个人物强制设为清晰，也不声称能恢复被遮挡的背景。
- 点击人物时，使用该人物可靠区域的深度分布，适度放宽其清晰范围，减少估计误差导致的脸部、头发与躯干误糊。低置信边缘和深度离群部位不直接设为清晰；背景与其他人物保持原来的深度规则，点击背景会重新换焦。首次处理与拍后编辑使用同一规则。
- 可靠的人脸深度可补充人物核心范围，避免全身照中的小面积头部被当作离群值。只有深度已判定清晰、人物置信度足够高的核心像素才额外保留原图细节，防止低分辨率虚化图上采样时糊掉小脸；不会把失焦手臂或背景一起恢复清晰。
- 模糊工作图最长边限制为 2048，最终输出保持原图尺寸。虚拟 f 值控制视觉虚化量，并非真实镜头光圈。
- 原生深度不适用时自动估计；模型失败保留普通原图和错误诊断；景深关闭时不加载或运行模型。
- 细发丝、透明眼镜、反射和大幅遮挡仍需真机画质验证。当前边界处理使用 RGB 引导，没有将人物分割作为全人物保护遮罩。

真机验收：分别选择三个镜头拍照，查看 TestLog 中物理镜头选择、实际输入、主摄锁定、照片 `sourceDeviceType` 和深度交付。主摄辅助输入允许 `isVirtual=true`；超广角、长焦必须为独立物理输入。测试捏合、前后摄往返、重拍及连续切镜头后的预览和成片。代码/合成测试不能代替设备验收。

## 主摄苹果渲染路径

- 主摄交付有效原生深度后，拍照和后续编辑接入此前的 `CIContext.depthBlurEffectFilter` / `CIDepthBlurEffect`，虚拟光圈交给苹果滤镜处理；旧文档和显式苹果对照继续使用同一路径。
- 原生深度缺失或苹果滤镜处理失败时回退智能景深，在诊断中记录 `appleFallbackReason` 和实际渲染器，结果不会标为苹果景深。
- LiDAR 在配置和快门时都验证输入身份与唯一物理主摄配对；`activePrimaryConstituent` 缺失或指向非 RGB 设备时不再直接降级，明确指向另一物理 RGB 镜头仍拒绝。双摄/三摄继续核实精确主摄与锁定状态。
- 相机在内存 HEIC/JPEG 中保留原生深度、元数据及可用人物遮罩，并按当前设备能力请求头发、眼镜遮罩。
- 苹果路径不再把整个人物用原图强行拼回清晰区域，允许同一人物不同距离部位呈现景深变化。
- 旧版自算深度虚化保留为对照，方便检查背景人物、椅背和黑色衣物等区域的变化。
- 官方滤镜内部虚化遮罩不公开。苹果结果的诊断图是**输出与原图的像素差异，放大 4 倍**，不称作真实虚化量图。
- 成功状态仍检查实际输出像素变化；微弱变化会提示弱效果。像素变化不是画质合格证明。

当前 macOS 实测发现部分辅助元数据会让官方滤镜直接返回输入对象。完整原生元数据路径优先；仅在确认这种原样直通时，移除滤镜和视差图上引发直通的辅助元数据包装，再由同一个苹果滤镜处理。真实视差值、可用遮罩和独立标定输入保持不变。结果页明确显示 **苹果景深（兼容）**，诊断记录触发原因。该兼容处理不是旧版算法回退；其是否在 iPhone 18 上触发及实际画质仍须真机验证。

## 数据和效果边界

所有图像处理在本机执行，估计深度时使用随 App 打包的 Core ML 模型，无网络服务或第三方运行 SDK。可编辑照片在 App 的 Application Support/TestCamer/EditablePhotos 中保存完整原始容器、初始/当前焦点与光圈，以及预览；计算景深还保存独立深度附件，苹果景深使用容器内原生附件。原图和深度不可变，参数与预览通过版本目录和原子指针一起提交；校验和用于发现文件损坏。保存失败明确提示并保留上一有效版本；超过 24 小时且不活跃的合法首次保存暂存包在读取图库时回收。旧版 schema 1 文档继续可读。

系统相册收到的仍是白名单编码 sRGB、8 位 JPEG（质量 0.95），不复制深度、焦点、MakerApple 或可重编辑参数；虚拟 f 值不写成硬件 EXIF 光圈。系统相册不能凭这张 JPEG 重新换焦，需返回 App 的可编辑照片；卸载 App 会移除其本机可编辑源数据。

关闭景深、深度估计或渲染失败时，保留普通照片并显示原因。原图本身的光学失焦不能通过拍后换焦恢复；长焦近距离拍摄尤其需要在快门前正确物理对焦。

用户提供的 `iPhone18tu.heic` 是**已经呈现虚化的系统参考成片**。它可用于观察目标效果和输入结构，不能再套一遍滤镜后把二次虚化当作公平 A/B。正式视觉验收需要新的真机拍摄：同一场景、相近构图和距离、同为 f/1.4，并检查完整成片而非只看截图。

## 苹果旧路径的已知画质差异

**尚未通过“选择远处时，近处明显虚化”的录屏验收。** macOS 与独立 iOS 27 / iPhone 18 Pro 模拟器的同一未虚化合成 HEIC 测试均发现：公开苹果滤镜能在点近处时模糊远景，点远处时恢复远景清晰，但近处纹理仍保持清晰。完整 metadata 路径在该输入上直接返回原图；兼容 factory 与直接 RGB+disparity 路径表现相同。此结果不能直接外推到真机照片，但也不能把 API 接入或交互完成称为与系统“照片”效果一致。

标准回归独立报告这些苹果路径差异；严格运行 `bash Scripts/verify_photo_editing_render.sh --require-foreground-blur` 仍会暴露该已知限制。主摄恢复苹果流程也保留其限制；其他镜头及回退路径标注为智能景深，用独立像素测试验证近景与远景虚化，不把计算渲染结果归功于苹果滤镜。

## 诊断与 TestLog

拍摄页和普通成片页右上角可导出 TestLog；编辑页的拍摄对照提供初始诊断。日志包含设备能力、辅助数据是否交付、渲染路径、处理耗时、输出变化及错误；不写入照片、完整深度图、焦点坐标或人脸框。日志在本机轮转保存，最多 3 个约 1 MiB 分段；导出后由用户自行选择分享目标。

景深诊断注明 native/estimated 来源、实际处理路径及失败原因。智能景深显示虚化量图，苹果对照显示像素差异图，两者含义不同。


```bash

```

```bash
bash Scripts/verify_apple_depth_on_mac.sh
```

测试覆盖以实际测试文件和运行报告为准。合成图像测试可以发现参数、方向、焦点、回退和导出问题，不能替代 iPhone 真机的发丝、眼镜、多人背景与相册保存画质检查。

新增验证：`verify_monocular_depth.sh` 运行实际模型；`verify_computational_depth.sh` 验证前后景像素变化；`verify_computational_pipeline.sh` 验证 RGB-only 输入、方向、深度来源、失败回退和拍后复现；`verify_main_camera_capture.sh` 检查主摄辅助输入筛选；`verify_main_camera_rendering.sh` 检查主摄苹果效果与重开编辑一致。真机步骤见 `Documentation/2026-09-22-三镜头智能景深验收.md`。

## 同帧离线回放

仅使用**尚未添加算法虚化**的相机原图和同一快门的原生深度。若原图已包含辅助深度，前两个参数使用同一个文件：

```bash
bash Scripts/replay_depth_photo.sh original-with-depth.heic original-with-depth.heic /tmp/depth-comparison 1.4 0.5 0.5
```

焦点参数是原始照片传感器坐标（左上原点、归一化），可整体省略；并非屏幕截图的坐标。分离素材必须尺寸、方向一致且来自同一次快门。

输出 `rendered.jpg`（苹果主结果）、`legacy.jpg`（旧版）、`original.jpg`（原图预览）、`difference.jpg`（输出差异）和 `report.txt`。回放文件只由命令行工具写入指定目录；App 的可编辑照片采用独立本机存储。

## 主要代码

- `CameraManager.swift`：相机能力、快门、原生深度与辅助遮罩交付。
- `AppleDepthRenderer.swift`：苹果官方景深适配、焦点与方向、输入校验。
- `MonocularDepthEstimator.swift`：离线 Core ML 深度估计、输出验证与比例恢复。
- `ComputationalDepthRenderer.swift`：统一近景/远景虚化，不做全人物强制清晰。
- `PhotoDepthData.swift`：带版本和来源的不可变深度附件。
- `DepthPhotoProcessor.swift`：后台处理、同帧对比、回退、输出变化检查及 JPEG 编码。
- `DepthBlurRenderer.swift`、`DepthMath.swift`、`PortraitSubjectMask.swift`：保留的旧版对照实现。
- `ViewController.swift`、`DepthDiagnosticsViewController.swift`：取景、普通成片与诊断。
- `PhotoEditingModels.swift`、`EditablePhotoStore.swift`：可编辑文档与原子本机存储。
- `PhotoEditingSession.swift`：最新请求胜出、失败恢复与屏幕坐标映射。
- `PhotoEditingRenderer.swift`：原图重渲染、预览和完整尺寸导出。
- `PhotoEditorViewController.swift`、`EditablePhotoLibraryViewController.swift`：成片编辑、本机照片重开与删除。
- `CaptureComparisonViewController.swift`：初始同帧对照。

`Documentation/` 中 v2 实现和画质修复说明是历史记录，不代表 v3 已经完成真机画质验收。
